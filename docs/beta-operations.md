# Beta operations

This phase supports invited gamers using non-withdrawable TEST credits. Set BETA_MODE=true, ENABLE_TEST_CREDITS=true, INITIAL_TEST_CREDITS=100, PLATFORM_FEE_BPS=500. Configured limits are MAX_OPEN_CHALLENGES_PER_USER (default 5), MAX_DAILY_CHALLENGES (20, UTC day), MAX_STAKE_TEST_CREDITS (100), MAX_EVIDENCE_SIZE (52428800 bytes), MUTATION_RATE_LIMIT (60 per actor/controller/action/minute). Validation rejects malformed booleans and nonpositive/overflowing limits. Critical production database/Redis URLs and JWT secret are checked at startup. Fee policy validates 0..10000 basis points. Test credits default off unless explicitly enabled.

Challenge caps are checked inside the serializable creation transaction; rate counters use atomic Redis INCR/expiry and do not depend on user-supplied identifiers or forwarded IP headers. Redis failure denies affected mutations safely. Existing auth limits remain Redis IP/action based. Serializability, idempotency and ledger accounting are preserved.

ADMIN-only GET /operations/summary returns aggregate counts and dependency health; /operations/funnel returns distinct-user participation/funding/start/completion/repeat counts and rates. The admin application's /operations page reads the safe summary server-side; MODERATOR alone cannot access operational data. Daily counters use UTC. Completion includes SETTLED or REFUNDED. Challenge completion/cancellation denominators are all challenges; dispute/refund denominators are all matches. Repeat means more than one completed match.

ADMIN-only /operations/metrics emits Prometheus text: bounded method/route-template/status HTTP counters and latency histograms plus persisted product-event counts derived from append-oriented audit events. Count attempts/failures from HTTP route/status counters; committed success events come from transactional audit rows. Do not attach user IDs as metric labels. HTTP counters are process-local: scrape each instance; audit totals are database-global and must not be summed across instances. No commercial analytics vendor or sensitive payload is sent.

Structured request logs contain time, level, service, random request ID, method, route template, status, duration and authenticated actor ID. Error logs expose only class and safe Prisma error code, never error messages/stacks/queries. No passwords/tokens/cookie values or evidence bodies are logged. Restrict log access and set retention. Health/live checks the process; health/ready checks PostgreSQL and Redis with a bounded wait. /health retains the prior compatibility contract. Public health failures do not reveal connection details.

Run `node scripts/ledger-invariants.cjs` on a schedule and after incidents/restores. It reads a consistent snapshot, checks global conservation, every transaction, and nonnegative user/vault balances. Failure logs CRITICAL and exits nonzero. It never repairs entries. Scheduling/alert routing is an operator responsibility; no external notification integration is added.
